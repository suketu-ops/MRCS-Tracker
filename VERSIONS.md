| 2026-08-21   | `v122.0`  | v121 + cross-device drill history | The per-question drill memory (seen/right/wrong/streak — what weakest-first ordering runs on) was localStorage-only by design since v119: fine for one device, wrong once drilling happens on iPad flights, the MacBook and the iPhone. New Supabase table `mrcs_drill_history` (one row per drilled question, keyed by the same qhash/djb2 key the local store uses; `n_right`/`n_wrong` because RIGHT is a SQL reserved word). **Push**: answering marks the question dirty; dirty keys flush in one batched upsert 5s later; a misclick override bumps `last` and re-flushes so the override wins the merge. **Pull**: at boot AND right before a drill queue is ordered (2.5s budget, silent local fallback offline/slow) — a session finished on the MacBook re-orders the iPhone's very next drill. **Merge** is order-insensitive and convergent: lifetime counters take element-wise max (never regress); streak/conf/last — the fields `drillPriority()` orders by — follow whichever device holds the LATER attempt. The v121 resync sweep gained an isolated drill-history section (own try/catch — can never block session/tracker/card resync), so offline drilling strands nothing. Verified against production: device-A dirty-flush wrote a real row; device-B pull flipped that question's priority from unseen(1) to failed-leads-queue(0); synthetic row deleted afterwards. In-app 📋 SQL setup extended with the new table. No sw.js change. |
